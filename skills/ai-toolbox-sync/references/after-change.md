# 新增、更新与恢复后的结构化处理

## 当前机器与事件范围

已有受管资源修改前检查、结束仅提醒及用户主动同步使用 [任务触发流程](task-sync.md)。本页只处理新资源决定及操作结果，不因同步失败重开加入询问。只读检测不写决定、不安装、不上传；用户明确要求将已核实范围的自建未同步资源加入并同步时已构成该范围决定，只有来源或目标歧义才问。

先核对本机绑定、真实文件和宿主实际收到的指令，分别报告文件安装、Skill 可发现、真实触发。接入状态逐机核实，不沿用旧报告当作当前状态。Skill description 和全局规则不是外部手工安装事件监听；没有后台扫描。外部安装只在用户主动检查且已授权的非敏感来源中补充发现，不读取凭证、环境文件或完整敏感宿主配置。

只有安装外部资源完成或用户主动要求收集时才集中处理；新建 Skill（含开发验证安装）不主动收集、不询问纳管或同步。每项保留真实成功或失败状态，不以批量整体成功代替逐项结果。用户明确排除的资源不询问；管理器安装/优化不构成管理器自纳管同意。由另一个聊天负责询问时，不重复询问或并发写同一决定。

## 稳定身份与事件决策表（流程规则，不是自动事件引擎）

先读获准清单与本机 records，查既有 id，再核对 kind + sourceIdentity。不能仅用名称、版本、当前目录、时间戳生成身份。

| 事件 | 处理 |
|---|---|
| 新安装的外部独立资源 | 无既有决定且有可保存内容时纳入本批结构化询问；纯新建不触发 |
| 同名异源 | 按已核实来源分开；不同独立资源分配不同稳定 id，不按名称合并 |
| 重命名、目录移动、来源迁移且确认仍是同一资源 | 沿用原 id/sourceIdentity；更新显示名，路径在本机绑定处理。无法确认身份先核对，不把未知当新资源 |
| 用户主动要求收集的自建资源 | 首次登记可用一次性 UUID 作为稳定 id；sourceIdentity 采用持久项目身份。后续名称/路径变化不生成新 id |
| 原有名称式 id | 兼容保留，不为了新规则重新编号或拆掉历史；先核对来源，填充缺失 sourceIdentity |
| 插件内置 Skill/MCP | 默认随父插件整体处理，不逐组件重复问；仅用户明确要求独立保存时单列，并记录 parentId 和独立范围 |
| 已收藏版本/内容更新 | 不问“加入”；核对差异、目标库/分支/资源/操作授权，修改结束仅提醒是否同步；用户主动同步时范围内延续执行，超范围只问新增范围 |
| 已收藏资源在新机恢复 | 不重问加入；安装/应用仍按已有目标授权，安装成功与可调用分开 |
| 某机器卸载 | 只更新本机 installation=uninstalled；不删除共享源码或清单，不把 collection 改成未收藏 |
| 源码创建成功、安装失败 | 明确“源码已完成，安装失败，未验证调用”；仅在用户主动收集时可只收藏源码，不主动询问，不假称安装成功 |
| 创建失败且无可保存内容 | 仅报告失败，不问收藏不存在的产物；已有合法版本不受影响 |
| 仅添加可迁移配置定义 | 可询问收藏该定义，installation=configured；不称 installed 或已验证 |

sourceIdentity 是稳定来源身份而非敏感 URL；同一来源中的不同独立组件必须区分持久组件标识。来源地址/子目录变化不必然是新身份，先核对既有归属。来源无法确认时暂停身份写入，不用 guessed/unknown 把多个资源合并。

## 拒绝、稍后、未答复

- declined（不加入）：普通版本升级、文件摘要变化、重命名、移动、安装重试不会推翻拒绝，不反复问。
- 只有用户主动重新考虑，或已核实独立身份/用途/拟保存范围实质改变时，才说明“具体改变了什么、为何不再是原询问”，按新范围重问；版本号变化本身不满足该条件。新独立身份另建记录，旧拒绝保留；同一身份用途/范围变化保留历史决定至用户新答复。
- deferred（稍后）：等待用户主动检查或重新考虑，不等同永久拒绝，也不设置后台提醒。
- pending（未答复）：本聊天已问过则保留待定，不重问同一事件；主聊天已问管理器自纳管但未答复时保持未决定，不因为本轮优化写 approved/managed。
- 用户主动“检查待处理”时集中列 pending/deferred；declined 默认不混入，除非用户要求查看拒绝项或重新考虑。批量逐项选，不默认全选。
- 跨聊天主动提示没有原子预占/投递确认机制，不能承诺 exactly-once；先核对任务负责方与现有 prompted 记录，遇并发不确定暂缓自动问，交由指定聊天集中处理。记录写入锁不能把 UI 提问和落盘变成一个事务。

## 统一询问卡片

每项必须提供以下内容（批量使用一张逐项表，允许同批不同决定）：

| 字段 | 必填内容 |
|---|---|
| 资源 | 显示名、Skill/MCP/插件、真实来源及自建/第三方；必要时用稳定 id 区分同名 |
| 当前结果 | 源码完成/安装完成/仅配置/安装失败等；验证状态单列，不用笼统“成功” |
| 将保存什么 | 自建 Skill + 许可、自建源码、第三方安装来源/提示词/版本资料；明确排除凭证/机器数据 |
| 目标与同步范围 | 仅本地收藏，或具体已授权库/分支/资源与允许操作/触发方式；没有授权就写“不上传” |
| 用户选择 | 加入 / 稍后 / 不加入。没有答复保持 pending，不替用户选择 |

示例：**笔记工具 · Skill · 自建项目 X**；源码已完成，安装失败、宿主调用未验证；保存已审核源码及许可；目标为本地工具箱，不上传。**加入 / 稍后 / 不加入**。

已授权库示例：保存到“指定库/指定分支”，参与已授权的手动同步；说明这个新条目进入哪一范围后询问加入。同意加入后仅收藏，不自动上传；用户主动要求同步时，不重复问相同上传权限。笼统“加入”不扩展到另一库/分支、删除、覆盖、登录、后台调度。既有授权查本机 binding 和真实会话依据，记录不能制造授权。

## 执行和持久化顺序

1. 核对本批事件、身份、既有记录、用户指定负责聊天及上述分支，准备结构化卡片。读取 [记录辅助](decision-records.md)。
2. 询问仅在确需用户新决定时发出；实际提示后可在获准记录范围保存 prompted=true、decision=pending。没有记录写授权只报告聊天内待定，不暗中写入。发送和记录不是原子操作。
3. 收到明确答复后，使用辅助的 inspect → 带 expected SHA 的 update 保存 decision=approved/deferred/declined 和真实 decisionEvidence。非零退出不称保存成功，保留聊天答复、重读核对，不重新要求用户答复同一问题。
4. approved 后才进行已有授权覆盖的复制/登记；实际成功后仅设 collection=collected，失败设 collection=failed，decision 仍 approved。记录写失败不能倒推资源不存在：先检查实际落盘，禁止盲目重复复制。
5. 没有本次同步请求不 commit/push，保留未同步状态。安装、同步、目录刷新各自更新 state 对应轴。已收藏而上传失败只设 sync=failed；刷新失败只设 catalog=failed；不能重开加入询问或撤销 collection。成功再分别设 synced/current，不在运行前预记成功。
6. 已收藏条目和本机记录的 state 为同一语义：共享清单只持久化可共享的能力/来源/收藏信息，本机 installation/sync/catalog 和用户决定留本机 records；目录生成时显式传入已批准的记录文件，按稳定 id 只合并五轴状态，不导出记录全文。见 [目录](catalog.md)。
7. AI 整理 categories、summary、triggerPrompt 后刷新目录。目录刷新失败独立报告，保持决定与收藏结果。可把 catalog=current 在刷新成功后写入记录，再重新生成展示数据；第二次生成失败如实记失败，不能把之前一次成功外推到最终产物。

本流程没有实现自动资源复制/安装或 Git 引擎；执行仍由 AI 在已授权范围调用既有 CLI，前置检查见 [同步边界](safe-sync.md)。证据、错误和来源需非敏感且最小化。

## 第三方资源边界

源码同步仅允许权威清单 ownership=self 的已授权资源。开始/收尾均核对 taskSync.resourceIds、实际 source 内容、CLI 全部目标及待提交路径；第三方或归属未知资源混入时停止相关同步，不靠网页过滤代替执行检查。第三方 Skill/MCP/插件只登记安装来源与提示词，实际版本/安装状态留在库外；不 collect 或复制其目录。第三方最新版检查与更新独立走 [更新流程](third-party-updates.md)。授权只来自当前用户对具体仓库、分支、资源和操作的明确选择；不继承发布者的授权。


## Agent 文档

整份全局文档使用 `kind=agent-document`，按 [Agent 文档流程](agent-documents.md) 发布、导入及同步。复制导入提示只表达意图，执行时仍须确认目标与覆盖/整理/追加/插入方式。新派生文档登记独立身份，来源固定到提交；本机整份绑定不能随 Git 分享。目录新增 Agent 文档分类，支持复制导入或同步指令；同步指令必须匹配本机自己的绑定，无绑定时停止。五轴状态沿用，不将本地快照写成功或目录复制成功当成 GitHub 同步成功。
