# 首次配置：没有仓库也由 AI 完成

适用于用户要求“配置个人工具箱”“我没有仓库”“从零开始”。这是 AI 执行流程，不是后台安装器。用户要求实现或审查本流程，不等于授权替当前用户新建真实仓库。已有绑定或已有仓库时转 [换机引导](bootstrap.md)，不能重复初始化。

## 1. 先检查，只询问必要决定

复用本会话已确认的选择和授权。先按 bootstrap.md 检查系统、架构、宿主、Python、Git、GitHub CLI、固定版本 Skillshare 和本机定位指针；只检查已知安装位置。依赖缺失在配置授权内由 AI 从官方来源安装并验证；需要管理员或登录操作时只交接该步骤。Python 是本 Skill 辅助脚本的必要运行时，不把 Skillshare 可执行等同于全部依赖齐备。

没有仓库时，集中给出具体方案，而不是让用户自行查参数：

> 我可以在你确认的 GitHub 账号下创建私有工具箱，建议名为 ai-toolbox；在本机独立目录保存同步源和本机状态。首次只上传空资源清单，之后由你选择收藏内容。是否同时启用新对话中的修改前比较并由你选择差异处理方式、修改结束同步提醒和安装后纳管询问？上传始终由你主动触发，日常使用与新建 Skill 不触发收集同步。

展示实际账号、拟用 OWNER/NAME、本机路径和操作范围；账号未认证时先完成登录再确认归属。默认建议私有库，不默认公开或组织账号。用户已明确要求按该方案创建并同步时直接执行，不重复确认。只要求本机使用或不愿创建仓库则跳过云端配置，明确云同步未启用。用户不必提供不存在的仓库地址。

路径按接收电脑规则选择，复用可用安装；不要复制开发电脑盘符、代理端口、仓库地址、身份或授权记录。目标已存在时先识别归属，不能覆盖或接管。同名资源、不同绑定、权限不符仅暂停相关步骤。

## 2. AI 建库，用户只处理认证

按 bootstrap.md 完成不输出凭证的账号检查和必要的官方网页登录；验证码、双因素认证和设备批准由用户在官方页面完成。已有有效认证直接复用。建库属于外部写入，必须匹配上一步已确认的账号、名称、私有可见性与创建授权。

先核实目标是否已存在。404 不能单独证明不存在：认证失败、网络错误和无访问权限分别处理。已存在则验证归属、权限与内容，转已有仓库流程；不删除重建，也不因为名称冲突擅自换名。

使用已安装 GitHub CLI 的 `gh repo create --help` 核实参数后，由 AI 执行 `gh repo create OWNER/NAME --private`（OWNER/NAME 必须替换为已确认值，不作为 shell 文本拼接）。不添加 README、模板或初始提交，以便识别真正空库。随后用 `gh repo view OWNER/NAME --json nameWithOwner,visibility,viewerPermission,url` 核实结果，再按 bootstrap.md 核实 Git 认证链路。

超时或返回不确定时先查询该确切仓库是否已创建，不能盲目重试、创建第二个仓库或改账号。成功但后续失败时保留仓库及阶段记录，不自动删除回滚。

## 3. 在全新目录建立空工具箱

建库和本机初始化阶段写库外的 `bootstrap-progress.json`，仅记录授权依据、账号/仓库名、路径、阶段、预期提交与实际核验结果；不保存设备码、Token 或凭证。恢复时先核对实际远端、目录及上次命令是否已结束，不凭记录断言操作成功。

按 safe-sync.md 在子进程中同时设置 XDG_CONFIG_HOME、XDG_DATA_HOME、XDG_STATE_HOME、XDG_CACHE_HOME 和 SKILLSHARE_CONFIG；先于任何 Skillshare 调用设置，避免帮助或版本检查使用默认缓存。不要改 HOME、CODEX_HOME、全局 Git 配置或系统代理。

核实固定 CLI 的帮助及 [init 参数](upstream/init.md)，在新空目录执行显式全局初始化：

```text
skillshare init -g --no-copy --no-targets --no-skill --git --git-root root
```

先用同参数的 `--dry-run` 审查，再执行并核对实际 Git 根、配置和 targets 为空。禁止裸 `init`：其非交互默认行为可能导入现有资源、发现全部目标并同步。不要用 `init --remote` 接管旧目录。

由 AI 创建实际清单 `toolbox.json`，初始为 `{"schemaVersion":1,"resources":[]}`；不复制示例资源、exampleOnly 标记或开发者授权。可创建说明文件与必要忽略规则，确认机器配置、缓存、绑定、日志和备份不进入 Git。使用已核实远端设置 origin；存在不同 origin 就停下核对，不覆盖。分支按已确认选择建立，不假定远端已有 main。

## 4. 空库首次提交与推送

空库没有共同祖先，不能伪造 remoteTip 或正常同步 baseline。本节只适用于本流程明确获准新建、Git 查询成功且确认没有任何 refs 的远端，以及由本流程创建的本地仓库。远端已有任意 refs、来源不明或本机已有未知提交时转已有仓库审查；不以“首次配置”绕过 safe-sync.md。

建立库外 binding（参考 ../assets/local-binding.example.json），填真实 CLI、XDG、gitRoot、远端、分支、授权与 journal；资源列表先为空。本次获准同步需启用工作流辅助 taskSync.enabled=true，authorization.trigger 在用户仅选择手动时保持 manual，授权证据只记本次初始化范围；这不授权写宿主规则或后续自动任务触发。不启用同步辅助时不可调用 begin，应明确同步配置尚未完成。按 task-sync.md 的 begin 获取仓库锁，范围变化前 release 后重新 begin；未取得锁不得提交或推送。

审核整个暂存区、工作区及全部待发送历史，只允许空清单、必要说明和已审核管理文件；配置不应因忽略规则遗漏而入库。首次提交前核实 Git 作者信息，缺失时只问必要署名并限定本仓库配置，不猜邮箱或修改全局身份。按固定 CLI 帮助使用显式 `skillshare commit -g`，记录真实 HEAD 和提交树；这是真实初始化内容，不是无意义测试提交。

推送前再次成功查询实际远端所有 refs，仍为空才继续；在库外阶段记录中保存拟推提交、分支和未完成状态。使用 `skillshare push -g`（不带 --pull、不强推），不调用要求既有远端 SHA 的普通 push intent 来伪造空库基线。此首次事务由流程锁和 bootstrap 阶段记录覆盖，不冒称 sync_session 已自动覆盖无 HEAD 的远端。

返回后重新核对指定远端分支 SHA、实际提交内容和工作区，只有预期提交已存在才记录首次上传成功。若推送结果不确定，先只读检查确切远端 SHA；相等则核验并继续，不相等或有其他提交则保留现场审查，不盲重推。始终释放自己的锁，保留未完成阶段记录。

## 5. 选择资源并启用任务入口

空工具箱创建成功后，按 [纳管流程](managed-resources.md) 让用户选择首批资源；可以先不加入。授权只覆盖所选资源，自建源码和第三方来源记录分开。新用户收到的 ai-toolbox-sync 本身不是因此变成他的自建资源：默认按第三方来源记录，不自动改 ownership=self 或复制进源码同步范围；来源不明先核实。不得复制开发者的完整工具箱或自动收集所有本机资源。

按 after-change.md 在库外保存决定，并在授权范围内建立资源映射和定位指针。已有不同指针先核对，不覆盖。纳管不自动上传；用户明确要求本次同步后按 task-sync.md 提交、推送、完整性核验及 baseline 建立；空资源列表不能冒充已完成某个资源的同步验收。

用户选择启用新对话入口时，在其授权的宿主指令文件中按 ../assets/host-after-change-rule.md 写入相应规则；保留原文、避免重复区块，检查更近作用域规则。用户不启用则保留手动调用能力。仅安装 Skill 不代表入口已加载；配置完成后说明新对话如何调用，只有实际新会话发现并执行过才报告触发已验证。不得安装后台服务或宣称已有聊天自动重载。

## 6. 验收与交付

按独立结果报告：依赖版本、本机绑定/定位、仓库归属与可见性、首次提交/远端 SHA、首批资源及文件完整性、目录生成、宿主发现和新对话触发。目录生成按 catalog.md 执行，空目录正常，不放示例资源冒充收藏。Git 成功不能替代宿主发现；没有资源时明确“空工具箱已就绪，尚未纳管资源”。

失败只停依赖该步骤的工作：登录未完成不报已连接，仓库创建成功但上传失败不报已同步，入口未验证不报自动触发。交付只给用户当前需要完成的必要动作及已有结果，不要求其手工执行 AI 能执行的初始化命令。
