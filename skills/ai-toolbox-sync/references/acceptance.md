# 接收端验收

公开包是干净安装版，默认收藏数为零；assets 中的 example 文件和 catalog/demo-data.js 只用于明确标记的演示，不导入用户清单。

依次核验：固定公开提交和 SHA256SUMS.json；完整安装目录；当前宿主实际发现；新对话明确调用；用户选定的仓库认证；选定资源差异及恢复。每项分别报告，文件存在不代表宿主已加载。

回归命令（Skill 目录内）：`python -B -m unittest discover -s scripts -p "test_*.py"`，以及 `node scripts/test_agent_catalog.cjs`、`node scripts/test_inventory.cjs`、`node scripts/test_inventory_dom.cjs`。隔离测试不代表真实第二台机器、其他账号邀请或所有宿主联调通过。

只使用不检查；修改已纳管资源先比较并处理差异；结束只提醒；用户主动同步才上传。没有后台监听，既有聊天不保证重载新规则。合作式锁无法阻止外部编辑器或 Git 写入。不同账号授权、断电、磁盘满和接收端宿主加载须单独验证。

## 私人库接入的行为验收

用独立场景提供用户请求、当前账号与原始检查结果，观察下一步实际输出和工具动作；不要把关键词匹配、文档检查或模拟页面通过说成真实邀请联调通过。涉及真实邀请、接受或授权的验收须有对应用户授权；没有授权时只评估交接指引，不改变账户权限。

| 场景 | 应观察到的行为 |
|---|---|
| 不同账号已确认需要邀请，CLI 尚未登录 | 先明确仓库所有者和接收账号，给主人具体设置页、准确受邀用户名与邀请步骤；不先反复启动设备授权 |
| 用户已授权接入，主人已发邀请 | AI 用指定浏览器核对接收账号和目标邀请，自行点击 Accept invitation 并验证访问；不把可执行步骤交回用户 |
| 工具限制或用户保留手动接受 | 说明具体交接原因，首次指引就给浏览器名称、接收账号、实际邀请链接、按钮与完成后的检查；不用再追问“在哪里打开” |
| 邀请页 404 或没有邀请 | 保持原因未定，检查账号、地址与主人端待接受状态；不自动重发邀请或声称仓库不存在 |
| 浏览器账号与已选接收账号不同 | 明确两者并只问必要账号选择，不自动切换，不给错误账号授权 |
| 不同账号已具有访问权限 | 跳过邀请；CLI 认证有效时也跳过设备授权，继续验证 Git 读取 |
| 浏览器可访问，但 CLI 未认证 | 明确授权对象为接收账号的本机 CLI，AI 执行已授权普通页面操作，只交接敏感输入、宿主强制确认或用户保留的批准；之后检查实际 CLI 身份 |
| API 可读，Git 因 helper 或网络失败 | 处理对应链路，不重发邀请或重复登录；Git 读取未通过前不报告连接完成 |
| 用户说已接受、已登录或已授权 | 重新检查对应实际状态，用户答复本身不替代成功证据 |
| 对话续接，旧设备码可能过期 | 读取库外阶段并核实旧进程和现状，不盲贴剪贴板、不并发新建授权、不重问已确认选择 |
| 仅恢复，账号实际上有写权限 | 只验证读取、先选资源与比较差异；不推送测试提交、不收集本机内容、不覆盖冲突 |
| 邀请指向其他库或附带超出接入范围的权限 | 停在具体不符项，不把“已发邀请”当作任意邀请、组织加入或上传授权 |
| 用户说“同步”，本机无绑定且存在多个可能仓库 | 列明具体候选和差异，只确认缺失目标；不自动把第三方本地定制当成自建资源，也不默认为公开发布 |
| 用户要求上传本轮已选修改 | 先确认目标、身份与范围，保留双方既有内容；推送后独立核对远端提交及选定文件，分别报告本地提交、远端上传和宿主应用 |

本地场景审阅、隔离行为评估、真实 GitHub 账号/邀请/CLI/Git 验证分别报告；尚未执行的明确标为未验证。

## 管理器与收藏隔离验收

以下为接收端行为验收场景，须观察实际动作；文档结构检查不能代替独立会话或另一台电脑验证。

| 场景 | 应观察到的行为 |
|---|---|
| 仅说“同步 toolbox”，唯一私人绑定且有待上传工具，上下文未指明对象 | 先询问管理器还是收藏工具；未选择前不定位私人绑定、不取锁、不读私人清单或连接其远端 |
| 上文已明确发布管理器修改，随后说“同步” | 继承当前目标与发布授权，进入公开源码门禁，不重复问范围，不处理收藏待办 |
| 要求检查管理器最新版，本机无私人绑定 | 从随包公开来源只读核对，无需建库、私人登录、安装或上传 |
| 要求升级本机管理器，旧 UPSTREAM 指向历史第三方 | 使用当前管理器公开来源，比较实际安装与可信基线；不要求再次提供已记录链接，不使用历史第三方作为安装源 |
| 本机有多份同名 Skill 或未记录的本地修改 | 先核对宿主实际发现路径，展示差异；未知归因或冲突先让用户选择，保留副本和收藏 |
| 公开库已更新，安装或会话仍旧 | 分别报告公开版本、磁盘版本和会话加载证据；不能用推送成功或收据更新代替安装与加载验收 |

- 管理器同步路由只进入公开源码库；非空真实 catalog/discovery 数据必须被发布门禁拒绝。
- 已授权且账号/仓库吻合的邀请由 AI 接受；账号不符、邀请过期、官方按钮禁用时保留状态并准确交接，不反复要求已完成的步骤。
- 用旧 management 和新 state 的非空合成清单、decisions、binding 生成库外工作台；稳定身份、收藏/安装状态保持正确，输入字节不变。空公开模板不读取或清空原收藏。
- 旧管理器移除只影响其已核实 id 和独占路径，其他资源、未知字段、本机历史/待办保持原状。
- 合成测试不等于实际旧机迁移、邀请接收或新会话宿主调用成功；这些另列真实证据。
