# 个人 AI 工具箱

这是独立维护的个人 AI 工具箱项目。收藏同步由原生 Git 和本项目执行入口完成，AI 确定本次目标、授权范围和真实冲突的处理；MCP/插件使用各自官方安装及宿主接口。版本历史以 Git 为准，本机保留安装映射、授权和恢复材料，无后台监听。

本管理器的公开源码与更新来源：[fofiwo/ai-toolbox-sync-skill](https://github.com/fofiwo/ai-toolbox-sync-skill)。私人收藏仓库由用户单独绑定；`UPSTREAM.json` 只记录历史归因。

## 同步前先分流

先确定同步对象，再定位绑定或访问远端。复用当前对话已明确的对象与方向；一个私人绑定、待上传工具或旧待办不能代替本次范围选择。

| 本次目标 | 执行入口 |
|---|---|
| 检查 ai-toolbox-sync 版本或差异 | [管理器维护与升级](references/self-maintenance.md)；只读核对公开来源、实际安装和远端，不安装或上传 |
| 更新本机 ai-toolbox-sync、升级干净管理器 | 同一维护流程；从公开来源比较并应用获准的新内容，保留本地定制，不上传收藏或公开源码 |
| 修改、同步或发布管理器的本地通用改动 | 同一维护流程；按已确认方向维护公开源码；本次明确发布/同步授权才提交上传，方向仍不明先问更新本机还是发布本地 |
| 同步已收藏工具或已选 Agent 文档 | [任务触发同步](references/task-sync.md)；仅操作选定私人绑定、资源与方向 |
| 只说“同步”“同步 toolbox”“更新工具箱”，上下文仍无法确定 | 先问“这次是更新 ai-toolbox-sync 本身、发布它的本地修改，还是同步已收藏工具？”；得到选择前不定位私人绑定、不取同步锁、不读私人清单、不 fetch/collect/commit/push |

两个范围都要处理时，分别核对目标与授权、分别验收。用户已明确范围就直接继续，不重复询问；“更新管理器”不包含上传收藏，“更新本机”也不包含公开发布。

## 入口

- 准备修改、续接已有修改、跨电脑更新、同步或发布 ai-toolbox-sync 自身，或私人库曾收藏本管理器：先读 [管理器维护与升级](references/self-maintenance.md)。修改前记录 start 基线，精确暂存后 finish，获准提交后 verify-commit；离线本地保存与正式发布分开。安装定制先比较并保留。自身源码只在公开源码库维护和发布，私人库不收藏管理器；先隔离收藏与本机状态，再执行独立升级。此分流优先于普通自建资源同步。

- 收藏与待收藏统一工作台：读 [盘点与选择](references/inventory.md)。用户要求打开本机工作台时，通过 `build_workspace.py --refresh` 检查已授权 Skill 目录并复用/更新库外缓存，再打开实际输出页；扫描失败保留旧快照并明确标记。离线页面自身不扫描、不联网、不上传。

- 本机资源盘点、按来源项目统计、HTML 勾选后生成收集提示词：读 [盘点与选择](references/inventory.md)。使用独立发现快照，不能把未收藏资源塞入正式工具箱目录；插件/Skill 集合按来源归组，未知来源保留独立。


- 发布、导入或同步整份全局 Agent 文档：先读 [Agent 文档](references/agent-documents.md)。以全文为单位；先确定覆盖/整理/追加/插入，导入后建立独立派生身份；只双向同步本机明确绑定的自己的版本。来源固定到 Git 提交，禁止跨宿主广播。

- 已明确要求同步收藏：先读 [任务触发同步](references/task-sync.md#收藏同步执行入口)。目录类自建资源与第三方来源索引调用 `sync_session.py sync --dry-run` 核对范围，再由同一入口 `sync` 执行；清单或绑定包含 Agent 文档时沿用 `agent_documents.py` 与既有全文事务，不送入目录执行器。Git 三方合并和清单按 ID 合并能够兼容且通过检查时直接继续，不因同一文件被修改就询问；真实冲突、身份变更、未知范围和未授权删除才暂停。Git 上传与安装应用分别报告。
- 仅使用不检查。准备修改已纳管资源时先读同一参考文档，定位绑定、比较三层并登记 mark-dirty。尚无本次同步请求时，有差异仍先说明并让用户选择，不借准备编辑自动提交上传。修改结束只提醒；不热替换运行进程使用的文件，不声称已打开会话重载。
- 用户只要求检测/审查：只读比较本机实际安装、受管源与远端，不能因此安装或上传；明确要求同步且范围清楚时延续授权，不重复询问。

- 首次使用、没有仓库或要求从零配置个人工具箱：先读 [首次配置](references/first-use.md)，由 AI 完成环境检查、建库、本机绑定和验证，用户只完成必要选择、登录与授权；不要求用户先手工建库。
- 接入已有私人仓库、处理邀请/账号/权限、换机恢复，或 CLI 缺失、版本/路径不明：先读 [接入与换机引导](references/bootstrap.md)。先明确仓库所有者、接收账号及浏览器/CLI 实际身份，再按当前状态处理权限；用户说邀请已发出时，AI 自行检查并接受本次接入授权内的目标邀请，再验证访问。仅将敏感输入、宿主强制本人操作或用户明确保留的步骤交接，并给具体账号、可点击页面、按钮与完成标准。
- 安装外部资源后或用户主动要求收集/纳管：先读 [新增后询问](references/after-change.md)，依据稳定身份集中处理，分开记录决定、收藏、安装、同步、目录刷新；源码完成但安装失败可只收藏源码。按既有授权询问：未授权同步库时只纳管；加入已明确授权的库时说明将参与手动同步；加入不等于立即上传。新建 Skill（含开发验证安装）不主动询问或收集。用户主动同步时不重复请求同范围权限。
- 收藏现有资源或在新电脑应用：读 [受管清单](references/managed-resources.md)。仅处理用户选定资源；不要先 collect 全部再删减。
- 提交、拉取、推送、分发、更新或恢复：先读 [同步前检查](references/safe-sync.md)。这些检查在任何隐式 sync 前执行，无法证明安全即停下，不用 force 绕过。
- Git 提交/取得/合并/推送、资源收集与安装、旧绑定兼容：读 [原生 Git 工作流](references/git-workflow.md)。Git 传输与宿主应用分别执行，不自动发现或分发其他目标。
- 核对交付声明或正式接入：读 [验收矩阵](references/acceptance.md)，按当前机器实际证据区分文件安装、指令收到、Skill 发现与真实触发。

- 查看目录或清单发生变化：读 [本地目录](references/catalog.md)，先阅读资源能力说明，由 AI 生成并持久化能力分类、功能概要及 Skill 触发提示到清单，再生成只读展示数据并刷新页面。默认空目录，示例不代表实际安装。

- 检查最新版或更新第三方 Skill/MCP/插件：读 [第三方更新](references/third-party-updates.md)，实时核对官方来源与本机实际版本；检查不安装，明确要求更新才执行。

## 工作边界

1. 运行依赖为 Python 3.12+ 与原生 Git；GitHub 账号/建库使用 gh 或获准的官方网页登录。复用已安装依赖，按本机实际版本核对参数，不安装其他工具箱管理器。资源专用依赖按需单独安装。
2. 首期目标为 Windows + Codex；测试目录中的 Codex 形状目标不代表真实 Codex 已识别。其他宿主按实际官方接口单独验证。
3. Agent 文档按独立文档身份与授权绑定同步，派生不冒称原创；下面的第三方源码限制仅指 Skill/MCP/插件。仅明确自建资源支持源码同步（ownership=self）；第三方 Skill/MCP/插件只收藏安装来源、提示词和版本资料，不复制资源目录进入同步库，不加入 taskSync.resourceIds 或本项目源码分发目标。第三方换机从官方来源核对最新版后安装；本机实际版本/检查结果留在库外。来源未知先核实，不能当自建。第三方上游的本地定制必须明确记录定制身份并由用户确认，不能为了同步自动改 ownership。
4. 凭证、登录状态、真实宿主完整配置不纳管；机器路径和本机决策记录留在仓库外。缺失来源/版本标记未知，不猜测。
5. 不默认删除、覆盖、强推、清理缓存或接管已有目录。删除默认保留，明确列出条目和影响，得到对应授权后再执行。
6. Git 同步与第三方升级分开。同步不顺便安装 latest。Git 成功、安装完成、宿主识别、MCP 调用、Skill 触发、插件加载分别报告。
7. description 不能保证跨任务触发。每机须核实已启用任务路由；新会话是否实际加载需单独验证。其他 AI 任务可采用 [宿主接入规则草稿](assets/host-after-change-rule.md)；本 Skill 不自行修改全局指令或安装 hook；用户明确导入/同步 Agent 文档时，仅按该文档授权范围处理。外部手工安装只能在后续检查补问。

历史第三方材料的来源与许可档案保留在 [UPSTREAM.json](UPSTREAM.json) 和 [历史许可](LICENSE.skillshare)，仅用于来源追溯，不构成运行依赖或产品隶属关系。

## 本机记录写入

状态与结构化询问见 [新增后流程](references/after-change.md)，实际写入使用 [记录辅助](references/decision-records.md) 的 inspect → 明确答复 → 带哈希 update；没有成功退出不能宣称保存成功。提示发送与记录写入不是一个事务，跨聊天主动提示不保证恰好一次。
