### 任务中的个人工具箱同步

仅使用 Skill、MCP、插件或读取全局 Agent 文档时直接使用，不调用工具箱同步检查，不联网、不扫描待办。

尚无本次同步请求时，准备修改资源先核对本机绑定/同步清单；未纳管不联网。已纳管的自建资源或自己的绑定文档调用 `$ai-toolbox-sync`，按 `references/task-sync.md` 与 `references/safe-sync.md` 实时比较安装、受管源、远端与可信基线。有差异先简述双方变化和建议，等待选择；不能借准备编辑自动提交上传。选择已明确不重复问；执行前变化重比，再登记 mark-dirty 开始修改。第三方只保存来源，不自动升级或复制源码；保留未知变化和其他聊天仍在编辑的现场，不热替换在用资源。

已纳管资源的修改任务每次结束（含阶段性结束）有实际改动且未同步时，只在最终回复末尾提醒一次“本轮改动尚未同步，是否现在同步？”。用户本轮已明确稍后/不同步则不重复问。不自动 collect、commit、push；已有上传权限只定义允许范围，不构成当前同步请求。跨会话保留未同步记录，聊天结束不等于修改完成；接手先核对负责方与现场，不替仍在编辑的聊天清账。

安装外部 Skill/MCP/插件完成后，对尚未纳管的资源按 `references/after-change.md` 集中询问加入/稍后/不加入；拒绝或未答复不重复问，加入不自动上传。新建 Skill（含开发验证安装）不主动收集、不询问纳管或同步，等待用户主动要求。

用户明确要求收集、同步、检查更新或换机恢复时执行对应流程：仅收集不上传，仅检查不安装。先区分公开管理器升级与私人收藏同步，范围明确不重复询问。收藏同步优先使用 `sync_session.py sync --dry-run` 和 `sync`，在既有明确库/分支/资源授权内允许精确提交、快进及经校验兼容的 Git 三方合并；不因有差异或同一文件双方修改就询问。真实内容冲突、身份/范围不明、未授权删除和有损安装覆盖才暂停并给出取舍。不得 reset、强推、自动 stash 或清除他人现场；无变化不造提交。新电脑先比较再恢复用户选定资源。上传前实时核对 scope、提交覆盖及远端，上传后核验固定提交；Git、安装和宿主加载分别报告，相关内容确已同步且原任务结束才完成对应待办并刷新库外目录。

本规则替代旧的使用前检查和任务结束自动上传触发方式。没有后台监控、定时任务或跨电脑广播；已打开聊天不保证自动加载新规则。Skill 不可用时如实说明，不自行安装管理器或扩大授权。
